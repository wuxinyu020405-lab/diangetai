# ── 安装步骤 ──────────────────────────────────────────────────────────
#   python -m venv .venv

#   pip install -r requirements.txt --only-binary=:all:
#   pip install --no-deps "blivedm @ https://github.com/xfgryujk/blivedm/archive/refs/heads/master.tar.gz"
#
# ── 为什么 blivedm 要单独用 --no-deps 装 ─────────────────────────────
#   源码用的是 blivedm 老 API：BLiveClient.set_handler + 同步 _on_danmaku
#   （见源码 L1752 / L2117-L2118）。
#   - PyPI 上的 blivedm 只有 0.1.0 与 0.1.1，都是重写后的 async 版
#     （add_handler + async def _on_danmaku），与源码不兼容；
#     且把依赖钉死到 aiohttp==3.7.4 / brotli==1.0.9，无法与现代包共存
#     （brotli 1.0.9 无 cp312 wheel，需源码编译）。
#   - 只有 GitHub master（v1.1.7）仍是 set_handler + 同步 handler，匹配源码。
#   - master 声明 aiohttp~=3.9.0 / Brotli~=1.1.0，但实测在 aiohttp 3.14.5 +
#     brotli 1.2.1 下构造与连接均正常（已验证 BLiveClient(room_id, session=...)
#     与 set_handler / stop_and_close），故用 --no-deps 安装，避免 pip 把
#     aiohttp 强行降级而破坏 qqmusic / blivedm 之外的代码。
#
# ── winsdk 注意 ───────────────────────────────────────────────────────
#   winsdk 是预发布版，PyPI 上 wheel 最高只到 cp312；Python 3.13/3.14/3.15
#   装不上。所以本项目固定用 3.12。
#   pip 默认不装预发布版，故必须显式写 ==1.0.0b10。
#
