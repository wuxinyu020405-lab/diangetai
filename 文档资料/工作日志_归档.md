### 2026-11-19 23:45 · R-25 歌词显示规则：只认 QQ 音乐 + 暂停不出词（已实测，未发版/未提交）

**用户原话**：「当点歌播放结束, 如果本地不是QQ音乐在播放的话, 也会去找歌词然后疯狂抖动, 不防改成只有本地是QQ音乐在播放时才出现歌词, 且不管是点播正在播的还是本地正在播的, 当他们暂停的时候, 直接不显示歌词」

**根因（查清楚了，不是表面问题）**

「疯狂抖动」是**两个 bug 叠加**：

1. **取词源头错了**：`system_media_worker` 原来调的是 `get_best_smtc_session(sessions_mgr)`（target=None，"谁在播就用谁"）。浏览器放视频时，SMTC 会把 Edge 的媒体会话暴露出来，视频标题**每秒都在变**（"xxx - 当前 1:23 / 共 10:00"），于是：
   - 每秒生成一个新 `track_key`
   - 每秒触发一次 `fetch_lyrics_by_mid_or_keyword`（拿视频标题去 QQ 音乐搜歌）
   - 每秒把 `active_lrc_lines` 整段换掉
   → 挂件上歌词疯狂闪、疯狂抖，还白白打 QQ 音乐接口。

2. **取词有空窗，加剧抖动**：旧代码先 `state.active_lrc_lines = []` **再**去搜词。搜索要 1~3 秒，这段时间歌词是空的；搜回来再填上。即使同一首歌，中途也会闪一下空白。

**改法（只动 `app_media.py` 和 `state.py`，没碰 mainapp）**

- `state.py` 新增 `local_bgm_paused = False`（本地 BGM 是否处于暂停态）。
- `app_media.py` 新增模块级函数 `lyric_paused()`：点歌播放（api）看 `state.paused`、本地 BGM（local）看 `state.local_bgm_paused`，两套暂停态各看各的、互不干扰。
- `lyric_sync_worker` 开头加判断：`lyric_paused()` 为真 → `current_lyric_info` 直接置空。**不清 `active_lrc_lines`**，所以一恢复播放歌词立刻回来，不用重新搜词。
- `system_media_worker` 的 local 分支：
  - 取会话改成 `get_best_smtc_session(sessions_mgr, "qqmusic")` —— **只认 QQ 音乐**。非 QQ 音乐的会话直接不取词。
  - 窗口标题兜底只在"完全没拿到 SMTC 会话"时才用（QQ 音乐最小化这类情况），有会话但暂停着就保持歌名，不再去猜别的窗口。
  - 每轮设置 `state.local_bgm_paused = not playing`（SMTC playback_status==4 才算在播）。
  - **取词改成"先搜、搜到再替换"**：不再先清空。搜的过程中歌词保持上一首/上一次的内容，不再闪空白。

**行为变化一览（挂件和界面同源，改完两边一致）**

| 场景 | 改之前 | 改之后 |
|---|---|---|
| QQ 音乐在播 | 出歌词 | 出歌词（不变） |
| QQ 音乐暂停 | 歌词继续跑/抖 | **不显示**（恢复即回来） |
| 浏览器放视频 | 拿视频标题去搜词 → 疯狂抖动 | **完全不搜、不显示** |
| 网易云等其它播放器 | 同上会乱取词 | **完全不搜、不显示** |
| 点歌播放中 | 出歌词 | 出歌词（不变） |
| 点歌暂停（pygame） | 歌词冻结（不清空） | **直接不显示**（恢复即回来） |
| 点歌播完回到本地 | 可能整首无词 | 正常（原有 api→local 修复保留） |

### 2026-11-19 18:50 · R-17 字体发虚（第2批）已实测：根因是云母半透明，关掉就恢复 ClearType

**怎么定位的（先测再改，没盲改）**
1. 先排除缩放：探针实测进程 DPI 感知 = 2（Per-Monitor V2）、屏幕 DPR = 2.0（物理 2560×1600 / 逻辑 1280×800）、Qt 逻辑 DPI 96；整窗截图 1932×1616 = 逻辑尺寸 ×2，**没有位图拉伸**。缩放这条路是干净的。
2. 再做 A/B：同一句 20pt 微软雅黑粗体，分别放进「普通不透明 QWidget 窗口」「透明窗口」「FluentWindow（云母开）」，各截一张真屏图，统计文字边缘的**子像素彩边像素占比**（有彩边 = 用上了 ClearType）：
   - 不透明窗口 4.48%（ClearType）；
   - 透明窗口 0.046%、FluentWindow（云母开）0.017%（全是灰抗锯齿）；
   - 云母关掉后 1.343%，回到不透明窗口同一水平。
3. 结论：**不是高 DPI 缩放没配，是窗口背景半透明**。Windows 上 Qt 只在「不透明表面」上开 ClearType 亚像素渲染；FluentWindow 默认用云母/亚克力，整窗半透明 → 整窗文字降级成灰色抗锯齿。在 175%~200% 缩放下，灰抗锯齿的字看着就是「发虚、像截图截上去」。

**提案：导航从 9 个标签改成 5 类**（按主播的使用场景分，而不是按技术模块分）
1. 直播台（首页）＝ 当前在播 + 队列（处理中/待播，删除/置顶）+ 切歌/暂停 + 快速加歌（点歌 / 本地点歌）+ 房间连接状态

### 2026-11-19 17:05 · R-14 UI 框架选型（只分析，没动代码）

**用户问**：「推荐用什么框架」——要 Win11 Fluent / QQ音乐那种观感 + 丝滑切换，Windows + Python，其它组件保留、只换 UI 层。

**核实到的事实**（gh 查询 2026-11-19）
- PyQt-Fluent-Widgets：**8167★ / 776 fork**，许可证 **GPL-3.0**，当天仍有提交；README 写明「GPLv3 仅限非商用，商用需购买授权」。
- 官方按 Qt 绑定分开发布：PyQt5 主分支，另有 **PySide6 / PyQt6 / PySide2** 分支；包名统一叫 qfluentwidgets，**不能同时装多个变体**。

**结论**：PySide6 + PySide6-Fluent-Widgets。观感最接近原生 Win11（导航/卡片/开关/亚克力现成）；项目本来就是 GPL-3.0-or-later，与 GPLv3 库兼容，私发朋友不商用没问题；PySide6 是 LGPL、官方维护、支持 Python 3.12；PyInstaller 有成熟 hook。

**影响面**
- pywebview（扫码登录）：最大风险。Qt 主循环接不了 pywebview 自己的循环，建议登录窗拆成独立子进程（跑完把 Cookie 传回），不要沿用现在的线程 patch。
- aiohttp（OBS 挂件服务）/ pygame（播放）/ pystray（托盘）：本来就在各自线程里跑，不受 Qt 影响。
- PyInstaller：装 PySide6 后包体积约 **+40~60MB**（压缩后），构建变慢；需确认 qfluentwidgets 资源打进去。
- 工作量：ui_ctk.py 约 1000 行整体重写 + mainapp 界面回调迁移（tkinter after/StringVar/messagebox → Qt），保守 **4~8 个工作日**（每晚 2~3 小时约 1~2 周）。

**备选**：① pywebview + 网页 UI（已有依赖，CSS 能做真 Fluent、动画 60fps，但要写 HTML/CSS）；② Qt Quick/QML（最丝滑，但等于再学一门语言，不建议现在上）。

**没做**：没改任何代码、没装依赖、没发版推送。

### 2026-11-10 21:30 · R-2 实现 + 建立本日志

**背景**：用户提出建立工作日志的要求，并顺手提了两条新需求。

**定位过程（R-2 为什么「最小才是正常」）**：

- 滑杆下限写死 `from_=100`（`ui_ctk.py`），JS 也只认 `spacing >= 100`（`overlay.py`）——这是第一层限制。
- 但即使把下限放开，视觉上也压不下去：`.lyric-line` 有 `min-height: 1.2em`，且 `padding: 4px 0` 是按 px 写死的（滚动模式 blur/hd 是 `10px/9px`）。行高系数小于 1.2 时，`min-height` 直接把间距撑住，所以「100% 看起来才正常」其实是 1.2em 在兜底。
- 结论：要真的能缩小，必须让 **min-height 和 padding 跟着行距系数一起缩**。

**改动**（全部在 `点歌台拆分/`）：

| 文件 | 改动 |
|---|---|
| `ui_ctk.py` | 行间距滑杆 `from_=100 → 60`、`number_of_steps=300 → 340`，提示语改「142% = 原始，可压到 60%」 |
| `overlay.py` | 新增 CSS 变量 `--lyric-lh-scale`（= 行高系数 / 1.42，默认 1 → **默认观感完全不变**）；`.lyric-line` 的 `min-height:1.2em` 去掉、`padding` 改为 `calc(4px * var(--lyric-lh-scale,1))`，blur/hd 的 `10px/9px` 同理；JS 钳制下限 `100 → 40`，并写出 `--lyric-lh-scale` |
| `state.py` | `line_spacing` 注释补范围说明（40~400） |
| `httpapi.py` | `_coerce_style_value` 里 `line_spacing` 原来跟 `size` 共用 `0~300` 钳制，**比滑杆上限 400 还窄**，单独分支改成 `40~400` |
