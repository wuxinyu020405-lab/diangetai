feat(login): 用 pywebview 内嵌浏览器替代 Selenium，登录不再产生残留进程

背景:
Selenium 每次登录都会拉起 msedgedriver.exe + msedge.exe 两个独立进程，
关闭窗口时 daemon 线程被强杀导致 quit() 不执行，驱动残留越积越多
（实测现场有 2 个残留 msedgedriver.exe）。

改动:
- browserlogin.py 重写，pywebview（WebView2 内嵌）替代 Selenium
  · 登录窗口是主进程内子窗口，随程序结束，零残留进程
  · Cookie 通过 window.get_cookies() 获取
  · 保留原有 Cookie 解析、直播间号查询、配置保存逻辑
- 解决 pywebview 与 Tk 的主线程冲突
  · pywebview 要求主线程，但 Tk 已占用，故登录在工作线程中运行
  · 两处绕过 _patch_pywebview_for_thread
    a) 线程名临时改为 MainThread（pywebview 是纯名称检查）
    b) signal.signal 在子线程打桩为空操作
  · 实测窗口/URL/Cookie 均正常
- main.py 自检模式改为检查 pywebview/WebView2 而非 selenium 驱动
- spec 增加 webview/pythonnet/clr_loader 收集，含 lib 下两套 WebView2 程序集

关键修复（我自己的 bug）:
_cookies_to_dict 原实现去 list 元素上找 .name 属性，
但 pywebview 返回的是 list[SimpleCookie]（每个只含单个 cookie），
导致 22 个 Cookie 全被静默丢弃、误判为读不到 Cookie。
修正后实测 22 个全部解析成功（buvid3/_uuid 等匿名 Cookie 均在内）。
未登录时没有 SESSDATA 属正常现象。

依赖升级:
pywebview 从 PyPI 6.2.1 换成 GitHub master，6.2.1 缺少 PR #1832
的 coreclr/WinForms 修复，装了必然启动失败（ContextMenu 类型缺失等）。

验证:
B站/QQ音乐登录页均可加载；Tk 与 pywebview 可共存；
登录流程走完无残留进程。
